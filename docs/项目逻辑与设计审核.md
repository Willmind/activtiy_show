# 项目逻辑与设计审核

审核日期：2026-09-19。本轮检查覆盖源码、现有简历、首页、8 个活动详情、图片查看器、手机布局、静态导出、离线导出和部署脚本。本记录描述审核阶段的结果；后续提交与发布状态以 GitHub 提交记录及 Actions 运行结果为准。

## 判断

正式作品集保留一套风格即可。目标是让 HR 快速了解候选人的行政能力、看到活动实物证据、下载简历并联系本人。四套主题的选择成本、样式分支和兼容维护，对这个目标帮助有限。

最终采用明亮展厅的布局：白色背景、深色正文、暖陶色标题、真实活动照片和统一圆角。借鉴 Apple 的留白与图片呈现、Linear 的克制层级，不照搬产品发布页的长篇营销叙事。首页大标题保留情感表达，作品、能力和经历区域使用更明确的内容层级。

## 内容问题：需要本人补充

### 1. 经验年限需要核对

现有 PDF 和网页写“5 年行政经验”，但已列出的两段工作经历是 2024.07—2025.07 和 2025.07—2026.06，总跨度约两年。可能存在未展示的更早经历，也可能需要调整年限。

本轮保留原始信息，已向用户询问；没有自行修改 PDF、编造早期经历或认定哪一项不实。建议在正式投递前统一网页、PDF 和求职平台的时间线。

### 2. 活动详情仍以现场记录为主

目前详情能展示活动照片、海报与氛围，但还不足以完整回答“她具体负责什么，怎样解决问题，最后效果如何”。这是下一步最值得补充的内容，优先级高于继续美化配色。

建议先选中秋、1024、圣诞等 2—3 个资料较丰富的活动，每个补充：

- 活动时间、所属公司、参与规模（可公开且能够确认的部分）。
- 本人实际负责的环节，以及独立负责、参与执行、协同设计的边界。
- 一个具体难点及解决办法。
- 可核实的结果；没有准确数据时用真实的完成情况，不强行量化。

50 人年会、90%+ 参与率、7.37% 预算节余、100+ 笔账单来自现有 PDF 的工作业绩，没有自动归属到某一张现场照片或某一场活动。

## 技术与维护判断

- 静态导出适合这个项目，不需要新增数据库、登录、后台或在线表单。邮件联系和简历下载已覆盖当前求职用途。
- 图片已是 WebP，并提供 480/768/960 宽度封面。大图在打开查看器后加载，长图分段；不建议为了更小的文件继续明显牺牲海报文字清晰度。
- 全部图片文件约 12.13MB 是完整素材库体积，不等于首页一次下载量。实际速度仍要在正式域名上线后用国内移动网络测量，本轮没有给出未经测量的加载秒数。
- GitHub 自动部署有专用部署账号、主机公钥校验、版本目录切换、健康检查和失败恢复机制，本轮没有发现需要重写的部署流程。
- 未修改服务器监听、DNS、HTTPS 或访问权限；本轮没有重新确认备案状态，也没有把本地改动发布到线上。
- 全量 `npm run lint` 仍有 **19 项既有错误**，位于未被当前作品集使用的通用模板组件及 `hooks/use-mobile.ts`，主要是可访问性、React Compiler 和图表类型规则。没有通过忽略这些目录掩盖问题；这部分列为低优先级模板清理事项。本轮实际页面、作品集组件、数据和脚本的定向检查通过。
- 页面仍使用既有基础 CSS 加作品集布局 CSS。多主题分支已经清除；若未来大改布局，再集中整理基础样式，当前没有为此引入额外框架。
