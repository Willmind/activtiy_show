# GitHub 自动部署到腾讯云轻量服务器

推送 `main` → GitHub Actions 安装依赖并构建 → SSH 上传静态成品 → 原子切换网站目录 → 本机检查。不需要在服务器克隆仓库或安装 Node.js。

现有 GitHub Pages 工作流继续使用自己的子路径构建。腾讯云工作流独立构建域名根目录版本，不修改 Nginx 监听端口、域名解析、备案信息或 HTTPS。

## 首次配置

初始化前提：Ubuntu 服务器已安装 Nginx；现有网站在 `/var/www/huiyi`；`/etc/nginx/sites-available/huiyi` 监听 `127.0.0.1:8081`。

1. 在自己的电脑生成**此项目专用**、无口令的 ED25519 部署密钥。私钥只存本机受限目录和当前仓库的 Actions Secret，不能提交到 Git 或上传到网站目录。若已经收到初始化包，对应密钥在本机忽略目录 `outputs/lighthouse-ci/`，无需重复生成。重新配置时可使用：

```bash
mkdir -p outputs/lighthouse-ci
chmod 700 outputs/lighthouse-ci
# 已存在密钥时保留原文件，不要覆盖。
test -f outputs/lighthouse-ci/lighthouse-deploy || ssh-keygen -t ed25519 -N '' -C github-actions-activtiy-show -f outputs/lighthouse-ci/lighthouse-deploy
```
2. 通过腾讯云文件管理上传 `scripts/setup_lighthouse_deploy.sh` 和公钥（命名为 `lighthouse-deploy.pub`）到 `/home/ubuntu`，在服务器执行：

```bash
sudo bash /home/ubuntu/setup_lighthouse_deploy.sh /home/ubuntu/lighthouse-deploy.pub
```

脚本创建专用 `huiyi-deploy` 账号，未授予 sudo 权限；SSH 公钥禁用终端和转发。可写网站目录为 `/var/www/huiyi-deploy`。当前网站复制为初始版本，原 `/var/www/huiyi` 留存备份；Nginx 的 root 改为 `/var/www/huiyi-deploy/current`，仍只监听原有本机端口。

3. 打开当前仓库 **Settings → Secrets and variables → Actions → Secrets**，添加两个 Repository secrets：

| 名称 | 内容 |
| --- | --- |
| `LIGHTHOUSE_SSH_KEY` | 专用私钥文件的完整文本，包含 BEGIN 和 END 行 |
| `LIGHTHOUSE_KNOWN_HOSTS` | 初始化脚本最后输出的整行服务器主机公钥，以 `129.204.51.116 ssh-ed25519` 开头 |

`LIGHTHOUSE_KNOWN_HOSTS` 必须来自你已登录的服务器控制台，不能直接信任未经核对的网络扫描结果。部署使用严格 SSH 主机身份校验。

4. 如果腾讯云防火墙当前把 TCP 22 限定为控制台或你的个人 IP，需要使 GitHub 托管 runner 能连接 SSH。先检查规则，不要修改已有 SSH 配置、开放全部端口或关闭防火墙。GitHub 托管 runner 出口 IP 会变化；需要固定来源时应采用具有固定 IP 的 runner。当前服务器若已经允许公网 TCP 22，则无需再增加规则。
5. 在同页 **Variables** 标签新增 Repository variable：`LIGHTHOUSE_DEPLOY_ENABLED`，值为 `true`。默认未启用时工作流会跳过发布。可选变量 `LIGHTHOUSE_HOST` 默认值为当前服务器 `129.204.51.116`，更换服务器时同时更新主机公钥及服务器初始化配置。
6. 打开 **Actions → 发布活动作品集到腾讯云 → Run workflow**，选择 `main` 执行首次验证。成功后，后续推送 `main` 会自动更新。

## 验证与回退

- `scripts/package_lighthouse.py` 检查首页、全部活动目录入口、简历、无 GitHub Pages 子路径、无符号链接后打包。
- `scripts/lighthouse_activate.py` 先解压完整版本，再原子切换 current；检查新版本标记、首页、七夕详情及简历 PDF。失败时恢复上一版并使工作流失败。
- 专用目录保留最近 5 个正式发布版本、初始版本和必要的回退版本。无效归档不会替换现有网站。
- 同仓库部署串行执行，不会中断正在上传或切换的版本。
- SSH 私钥仅在 runner 临时目录使用，结束时删除；不作为 artifact 保存。

本地验证发布逻辑：

```bash
python3 -m unittest discover -s scripts -p 'test_lighthouse_activate.py' -v
```

备案通过后，新增公网 HTTP/HTTPS 配置时使用同一个 `/var/www/huiyi-deploy/current` 目录，保留 `127.0.0.1:8081` 的内部检查服务。若改动该内部监听，需同步修改 `lighthouse_activate.py` 的检查地址。

自动部署流程通过仅表示文件发布完成。正式面试链接仍需备案通过、展示真实备案号、域名解析、HTTPS 和国内网络访问检查。

## 停用

将 `LIGHTHOUSE_DEPLOY_ENABLED` 改为 `false` 即可停止后续自动发布，不影响现有站点。永久停用时，再移除此部署公钥及对应仓库 Secret。
